sec-ssh-authkeys
================

堡垒机在例行巡检时发现，同一把公钥在不同授权文件里被理解成不同的能力集合：带空格的强制命令只剩第一个词，域名后缀约束把裸域也放行，来源网段把相邻网段一并算入，吊销名单里明明存在的指纹却匹配不上。契约要求：单行解析结果由选项集合、密钥类型、密钥主体和结尾注释四部分组成，四者边界必须严格，注释不得并入密钥主体；选项名按大小写不敏感识别并统一为小写，标志类选项没有值，带引号的值必须整体保留，引号内的空格、逗号、分号与反斜杠转义都属于值本身，不能被当作分隔符；可重复出现的允许连接项按出现顺序累积，主体名列表在引号内再按逗号拆分；空行与井号开头的注释行跳过，非法行只记录物理行号与固定原因而不中断其余行的解析；来源约束支持逗号分隔的多项，域名通配只匹配该域名的子域而不匹配裸域本身，网段按前缀位精确判定且只在同族地址间比较；连接目标比对必须同时命中主机与端口；否定类选项只有当上下文确实使用对应能力时才算违规；指纹以解码后的密钥材料计算，忽略其中的空白与换行，输出带标准前缀且不带填充；吊销比对忽略前缀大小写、空白与填充。不变量：单行解析与整文件扫描都是纯函数，结果只由输入决定；逐行处理时每条记录彼此独立，后一条不得继承前一条的选项；同一密钥重复计算指纹结果一致；吊销清单的顺序与书写形式不影响判定；选项集合中不出现仅大小写不同的重复键。
